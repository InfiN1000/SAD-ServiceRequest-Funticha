# Deployment (GitHub Pages)

Steps to publish the prototype on GitHub Pages:

1. Create a new GitHub repository named `SAD-ServiceRequest-Lastname` and push this project.
2. In the repository Settings → Pages, set Source to branch `main` and folder `/ (root)`.
3. Wait a few minutes; your site will be available at `https://<username>.github.io/SAD-ServiceRequest-Lastname/`.

Notes:
- Keep the Supabase service_role key out of the repo. The publishable/anon key in `js/supabase.js` is client-safe.
- Ensure Row Level Security (RLS) and policies are enabled in Supabase so the anon key cannot perform privileged actions.

Supabase table setup (run in SQL editor):

```sql
CREATE TABLE IF NOT EXISTS service_requests (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  requester_name TEXT NOT NULL,
  department TEXT NOT NULL,
  category TEXT NOT NULL,
  description TEXT NOT NULL,
  priority TEXT NOT NULL,
  status TEXT DEFAULT 'Pending',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  user_id UUID REFERENCES auth.users(id)
);

ALTER TABLE service_requests ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Authenticated users can view requests"
ON service_requests FOR SELECT TO authenticated USING (true);

CREATE POLICY "Authenticated users can insert requests"
ON service_requests FOR INSERT TO authenticated WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Authenticated users can update requests"
ON service_requests FOR UPDATE TO authenticated USING (auth.uid() = user_id);

CREATE POLICY "Authenticated users can delete requests"
ON service_requests FOR DELETE TO authenticated USING (auth.uid() = user_id);
```
